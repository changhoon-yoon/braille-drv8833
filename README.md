# braille-drv8833 — 점자 코일 벤치 테스트 (ESP32-S3 + DRV8833)

전자석 코일 1개를 시리얼 명령으로 조작하며 **팝 펄스폭**과 **홀드 듀티**를
실험으로 찾기 위한 펌웨어. 나중에 3×3(9코일)로 확장하는 발판이 된다.

## 배선

| DRV8833 핀 | 연결 대상 | 비고 |
|---|---|---|
| VM | 외부 5V (서플라이/어댑터) | ESP32의 5V 핀 아님! 모듈 가까이 470µF (긴 다리=+ 가 5V) |
| GND | 전원 GND + **ESP32 GND** | 셋이 반드시 공통 |
| EN / SLP | ESP32 **3V3** | 빼먹으면 전부 침묵 (1위 원인) |
| AIN1 | **GPIO 4** | 밀기 방향 |
| AIN2 | **GPIO 5** | 당기기 방향 |
| AOUT1 / AOUT2 | 코일 양 끝 | 방향 무관 |

개발 중 전원: 벤치 서플라이 5V, 전류 한도 1.2A 권장.

### ESP32-S3 (N16R8) 핀 주의
- **GPIO 26~37 사용 금지** — 플래시/옥탈 PSRAM 전용 (일반 ESP32와 다름!)
- GPIO 0, 19, 20, 43, 44, 45, 46 회피 (부트/USB/UART/스트래핑)
- 확장에 쓸 수 있는 안전 핀: **4~18, 21, 38~42, 47, 48**

## 업로드 방법

1. VS Code에서 이 폴더 열기 → PlatformIO가 자동 인식
2. 보드 USB 연결 (**"USB" 라벨 포트** 권장)
3. 하단 상태바 → (체크 표시) Build → (화살표) Upload
4. (플러그 모양) Serial Monitor 열기 — 115200bps

## 시리얼 명령

| 키 | 동작 |
|---|---|
| `u` | 올리기: 팝(100%, 펄스폭) → 홀드 PWM 유지 |
| `d` | 내리기: OFF (자석이 못 코어로 복귀) |
| `p` | 밀기 펄스만 (홀드 없음) |
| `q` | 당기기 펄스 (반대 극성) |
| `+` `-` | 펄스폭 ±10ms |
| `[` `]` | 홀드 듀티 ∓10 (0~255) |
| `s` | 현재 설정 출력 |
| `?` | 도움말 |

### 첫 실험 순서
1. `u` → 핀 올라가는지 확인
2. `[` 를 눌러가며 홀드 듀티를 낮춤 → **핀이 떨어지는 직전 값** 찾기 (+여유 20 더한 값을 코드 기본값으로)
3. `-` 를 눌러가며 펄스폭을 줄임 → **팝이 실패하는 직전 값** 찾기 (+여유 10ms)

## 트러블슈팅

| 증상 | 점검 순서 |
|---|---|
| 시리얼 모니터에 아무것도 안 나옴 | "COM" 라벨 포트에 꽂았다면 `platformio.ini`의 `ARDUINO_USB_CDC_ON_BOOT=1`을 `0`으로 바꾸고 재업로드 |
| 명령은 찍히는데 코일 침묵 | ① EN/SLP가 3.3V인가 ② GND 3형제 공통인가 ③ VM에 5V 오는가 (90%는 여기서 해결) |
| 동작하다 갑자기 침묵 | DRV8833 열 셧다운 — 1~2분 식히면 복귀. 홀드 듀티를 낮추라는 신호 |
| 업로드 실패 (포트 안 잡힘) | BOOT 버튼 누른 채 RESET 한 번 → 업로드 재시도 |

## 3×3(9코일) 확장 메모

- 핀/채널을 배열 테이블로 확장: 예) `{4,5}, {6,7}, {8,9}, {10,11}, ...`
- **주의: S3의 LEDC PWM 채널은 8개뿐** — 9코일 단방향(핀당 1채널)이면 딱 1개 부족.
  대응: 홀드 듀티는 모두 같으므로 여러 핀을 **같은 LEDC 채널에 공유 attach** 하거나,
  팝은 `digitalWrite`로 처리하고 홀드 중인 핀만 LEDC에 붙이는 방식으로 해결
- 팝은 반드시 순차 발사 (동시 발사 금지 — 전원·발열)
