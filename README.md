# braille-drv8833 — 점자 모듈 (ESP32-S3 + DRV8833 ×5, 9코일)

Pi 4(카메라 인식) → 시리얼 → ESP32-S3 → DRV8833 → 코일 9개(3×3) 구동.
1코일 벤치 튜닝 명령도 그대로 들어 있어 코일 하나만 물려도 동작한다.

```
[Pi 4 + 카메라] --USB(115200bps)--> [ESP32-S3] --> [DRV8833 x5] --> [코일 9개]
      pi/braille_cam.py                src/main.cpp
```

## 코일 핀 맵 (행 우선: 코일0=왼위 ... 코일8=오른아래)

| 코일 | IN1 (밀기) | IN2 (당기기/홀드) |
|---|---|---|
| 0 | GPIO 4 | GPIO 5 |
| 1 | GPIO 6 | GPIO 7 |
| 2 | GPIO 8 | GPIO 9 |
| 3 | GPIO 10 | GPIO 11 |
| 4 | GPIO 12 | GPIO 13 |
| 5 | GPIO 14 | GPIO 15 |
| 6 | GPIO 16 | GPIO 17 |
| 7 | GPIO 18 | GPIO 21 |
| 8 | GPIO 38 | GPIO 39 |

코일 0은 기존 1코일 벤치 배선(4, 5) 그대로.

### 공통 배선 (DRV8833 모듈마다)

| DRV8833 핀 | 연결 대상 | 비고 |
|---|---|---|
| VM | 외부 5V | ESP32의 5V 핀 아님! 모듈 가까이 470µF (긴 다리=+ 가 5V) |
| GND | 전원 GND + **ESP32 GND** | 셋이 반드시 공통 |
| EN / SLP | ESP32 **3V3** | 빼먹으면 전부 침묵 (1위 원인) |
| AOUT/BOUT | 코일 양 끝 | 방향 무관 |

### ESP32-S3 (N16R8) 핀 주의
- **GPIO 26~37 사용 금지** — 플래시/옥탈 PSRAM 전용 (일반 ESP32와 다름!)
- GPIO 0, 19, 20, 43, 44, 45, 46 회피 (부트/USB/UART/스트래핑)
- GPIO 48 회피 (데브킷 온보드 RGB LED)

### 전원
- 홀드 전류 어림: 코일당 풀온 ~1.1A × 실효 듀티(기본 27%) ≈ **0.3A/코일**
- 9핀 전부 홀드하면 ~2.7A → **벤치 서플라이(1.2A 한도)로는 3핀까지만.**
  완제품 데모는 5V 3A 이상 어댑터 필요. 펌웨어가 1A 초과 추정 시 WARN 출력.
- 팝은 펌웨어가 알아서 순차 발사(기본 60ms 간격) — 동시 발사로 전원 딥 안 생김.

## 시리얼 프로토콜 (Pi ↔ ESP32, 115200bps)

```
B:XXXXXXXXX\n     9자리 0/1, 행 우선(왼위→오른위, ..., →오른아래)
```
- 응답: `[OK] <현재패턴> up=<개수> (~x.xA hold)` 또는 `[ERR] ...`
- `B:000000000` = 전부 내림. 내림은 즉시, 올림은 순차 팝.

## Pi 쪽 실행 (`pi/braille_cam.py`)

```bash
pip install -r pi/requirements.txt
python3 pi/braille_cam.py --port /dev/ttyACM0        # QR 인식 모드
python3 pi/braille_cam.py --port COM5 --no-camera    # 키보드로 프로토콜만 테스트 (Windows에서도 가능)
```
- QR 내용의 **첫 글자(a~z)** 를 영어 1종 점자 6점으로 바꿔 왼쪽 2열에 출력
- CSI 카메라 모듈이 cv2로 안 잡히면 `libcamerify python3 pi/braille_cam.py`
- 종료(Ctrl+C) 시 자동으로 전부 내림 (발열 방지)

## 업로드 방법

1. VS Code에서 이 폴더 열기 → PlatformIO가 자동 인식
2. 보드 USB 연결 (**"USB" 라벨 포트** 권장)
3. 하단 상태바 → (체크 표시) Build → (화살표) Upload
4. (플러그 모양) Serial Monitor 열기 — 115200bps

## 벤치 튜닝 명령 (시리얼 모니터에서 사람이)

| 키 | 동작 |
|---|---|
| `0`~`8` | 튜닝 대상 코일 선택 |
| `u` | 선택 코일 올리기: 팝(100%, 펄스폭) → 홀드 PWM 유지 |
| `d` | **전부** 내리기 + 모든 자동 모드 정지 |
| `p` | 밀기 펄스만 (홀드 없음) |
| `q` | 당기기 펄스 (반대 극성) |
| `o` | 100% 연속 ON (전류계 확인용, 발열 주의) |
| `t` | 자동 반복 펄스 (선택 코일) |
| `r` | 켜고-끄고 교대 (60초 자동정지) |
| `+` `-` | 펄스폭 ±10ms |
| `[` `]` | 홀드 듀티 ∓10 (0~255, 홀드 중인 전 코일 즉시 반영) |
| `<` `>` | 반복 간격 ∓250ms |
| `s` | 현재 설정 출력 |
| `?` | 도움말 |

### 튜닝 순서 (코일마다)
1. `u` → 핀 올라가는지 확인
2. `[` 를 눌러가며 홀드 듀티를 낮춤 → **핀이 떨어지는 직전 값** 찾기 (+여유 20 더한 값을 코드 기본값으로)
3. `-` 를 눌러가며 펄스폭을 줄임 → **팝이 실패하는 직전 값** 찾기 (+여유 10ms)

## 내부 구현 메모

- **LEDC 채널 부족 해결**: S3의 LEDC는 8채널뿐이라 9코일 개별 PWM 불가.
  홀드 듀티는 전 코일 공통이므로 **홀드 채널 1개(CH0)를 공유** — 홀드 중인
  코일의 IN2만 attach하고, 팝/내리기는 digitalWrite로 처리.
- 홀드는 슬로 디케이: IN1=HIGH 고정, IN2를 PWM (LOW 구간 구동, HIGH 구간
  브레이크 — 전류가 순환해서 평균이 듀티에 비례. IN1 쪽을 PWM하면(fast decay)
  평균 전류가 붕괴함)

## 트러블슈팅

| 증상 | 점검 순서 |
|---|---|
| 시리얼 모니터에 아무것도 안 나옴 | "COM" 라벨 포트에 꽂았다면 `platformio.ini`의 `ARDUINO_USB_CDC_ON_BOOT=1`을 `0`으로 바꾸고 재업로드 |
| 명령은 찍히는데 코일 침묵 | ① EN/SLP가 3.3V인가 ② GND 3형제 공통인가 ③ VM에 5V 오는가 (90%는 여기서 해결) |
| 동작하다 갑자기 침묵 | DRV8833 열 셧다운 — 1~2분 식히면 복귀. 홀드 듀티를 낮추라는 신호 |
| 업로드 실패 (포트 안 잡힘) | BOOT 버튼 누른 채 RESET 한 번 → 업로드 재시도 |
| Pi에서 포트가 안 보임 | `ls /dev/ttyACM* /dev/ttyUSB*` — CH343 보드면 ttyUSB, 네이티브 USB면 ttyACM |
